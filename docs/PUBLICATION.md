# 发布隐私与项目依赖审计

[简体中文](PUBLICATION.md) | [English](en/PUBLICATION.md)

发布策略：**不公开被分析项目的源码或源码引文；截图是维护者允许的例外。** 工具的安装、运行、测试和演示无需任何外部私有项目、模型或缓存。

## 作者与历史信息

开发工作树共享原 Git 数据库，发布使用独立匿名快照，保留原仓库供本机恢复：

```powershell
node Tools/export-public.mjs --check
node Tools/export-public.mjs --export
```

从仓库根目录执行。导出在忽略的 `.release/` 下建立独立仓库，包含当前工作文件（包括尚未提交的修复），只有一个匿名根提交：

- 作者和提交者均为 `Architecture Explorer contributors <contributors@example.invalid>`，不公开个人邮箱。
- 不复制原 `.git`、祖先、分支、标签、notes、reflog、remote、签名、配置或运行缓存。
- 导出时隔离继承的 Git 身份和配置，关闭 hooks 与提交签名；新副本本机作者配置也使用匿名身份。
- 应从新副本推送明确的分支，避免推送原仓库的旧 refs。若已有远端包含旧历史，新匿名分支不会隐藏原有 `main`、标签或其他 refs。替换这些 refs 属于另一个需要明确授权的历史改写操作。

导出命令不 push、不创建远端。它在写入前检查公开文件依赖、文档链接、链接路径和隐私信息，遇到问题拒绝生成。已有远端缓存、第三方克隆或镜像中的历史无法通过本机导出撤回。

## 项目适配已解耦

| 区域 | 当前实现 | 回归与发布策略 |
| --- | --- | --- |
| 核心服务、网页、MCP 与索引器 | 项目、根目录和 Worktree 仅来自授权配置，无固定项目 ID、类名或流程 | 合成临时项目、空模型、多项目与 Worktree 测试；自包含演示独立扫描和审计 |
| 基础模型与语义定义 | `architecture/{models,semantics}/<projectId>/` 是可选内容，不存在时返回空业务模型 | 仅公开仓库内独立创作的 `combat-demo`；其他项目目录不复制，包括说明文件 |
| 语义种子链 | 从当前模型的任意流程生成保守候选；外部内容包须显式传入，纯 JSON，不执行插件代码，也不默认搜索私有目录 | `tests/semantic-seed.test.ts` 覆盖无包、自定义项目、包验证和 CLI；所有通用种子代码进入发布副本 |
| 故事/证据验收 | `Tools/validate-story.ts` 通过 JSON 声明符号选择器、关系和图要求，无内置领域符号；旧入口仅为兼容转发 | `tests/story-acceptance.test.ts` 使用合成源码；验收示例自带在仓库内 |
| 演示内容验收 | 原专用测试已换成自包含演示及合成边界夹具 | `tests/demo-architecture.test.ts`、`tests/demo-semantic-flows.test.ts` 进入完整公开测试，不再排除产品测试 |
| 通用编辑与候选生成 | 独立内存夹具，不在模块加载时读取私有模型 | `tests/semantic-content.test.ts` 保留编辑、分组、生成与存储回归 |
| 旧内容与历史材料 | 原始文件仅供本机恢复，不能补齐产品功能 | 私有模型不复制；历史文档生成中性双语说明，保留文档链接 |
| 截图 | 当前 README 只展示自包含演示 | 不含外部私有目标源码 |

外部内容包与配置驱动验收的格式、命令和安全边界见[项目内容适配](CONTENT-PACKS.md)。可选内容始终属于候选解释，不能升级静态证据或伪造人工确认。私有包和本机配置应存放在 Git 排除范围或仓库外。

## 发布验证

1. 完整运行分层测试、类型检查、分析器与网页构建；产品测试不依赖私有目录，也不因发布而被排除。
2. 执行公开导出预检及生成，在新副本内重新验证文档链接、完整测试、构建、演示扫描及证据审计。
3. 检查匿名作者和提交者、唯一根提交、干净工作区及明确的推送目标；不使用 `--mirror` 或默认推送所有 refs。
4. CI 在选择测试层之前执行发布预检；第三方依赖保留各自许可。项目授权方式见[许可说明](LICENSING.md)。

这里的独立性表示产品和回归不需要私有项目内容。发布检查不是对任意新内容的通用秘密识别保证，新增配置、文档和截图仍应检查其发布范围。
