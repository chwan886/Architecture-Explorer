# 双层语义架构图

在顶部打开「业务流程」。保留「领取驻守储量」和「开战→后续轮询→战斗结果」，并补充飞剑命中、锻造与穿戴、修炼与突破、探矿推进和事务保存五条源码流程，默认从简洁中文解释开始。独立请求和互斥分支不会被当成确定顺序；详见[源码复核记录](GAME-EVIDENCE-REVIEW.md)。「原始流程证据」仍可打开泳道证据板；系统总览、技术分层和原代码地图继续使用原有索引与界面。

## 看懂流程并追溯代码

- 「业务解释」显示主要步骤；「详细」或展开某组，查看其内部步骤、条件、循环与异步边界。局部展开只使用真实详细边，不会为了连接图形补造顺序。
- 「代码实现」显示同一流程映射到的方法、回调和真实关系。「双层对照」同时显示解释与代码，选择任意一侧会高亮另一侧的全部映射。一个方法可以参与多个解释步骤，一个步骤也可以关联多个实现。
- Inspector 显示目的、输入输出、处理、状态变化、映射和证据。点击语义连线可查看底层关系、逐跳有向调用路径与可信状态。跨 HTTP 请求、协议对应和其他无法静态证明的关联会保留未验证标记。
- 从实现进入原「代码地图」可继续调用链、读写关系和源码探索；使用返回入口回到当前解释。代码地图的「相关业务解释」也能反向打开对应流程。原有代码层导航历史、详情和源码选择保持一致。

折叠、预算或筛选会隐藏部分节点/关系，页面会明确提示。没有可证实调用的连线不等于代码不存在业务关联；有静态调用也不证明运行时必定执行，更不代表完整运行时数据流。

## 人工维护

所有初始解释均是有源码依据的候选，`curated` 表示源码整理，不代表用户已人工确认，也不代表运行验证。解释审查与原始代码事实的可信度独立；人工确认不会把未验证顺序提升为事实。

可编辑节点中文标题、职责、输入输出、处理和变化，合并/拆分摘要组，确认、拒绝或撤回审查。摘要分组必须完整且唯一地覆盖详细步骤；不会删除详细逻辑与控制边界。保存采用乐观版本校验，多窗口冲突保留草稿，可重新从服务读取最新模型后合并。

「规则候选」在本机用确定性模板整理现有内容，先预览、再由用户采用，不会自动覆盖人工内容，不调用外部 AI 服务，也不会生成新的代码关系。预览记录规则来源与生成版本；采用后保存为人工修订，规则提示仍保留在说明中，基础定义独立保留。未来接入 AI 时应单独配置，并增加独立的生成文本版本存储。

基础定义保存在工具仓库 `architecture/semantics/<projectId>/definitions.json`，人工覆盖和审查保存在 `architecture/semantics/<projectId>/worktrees/<worktreeId>.json`，历史由服务器维护并保留最近 100 次。覆盖文件适合随工具仓库提交以长期保存；派生 `.cache` 不提交。各授权项目、分支工作目录的覆盖/审查与缓存相互隔离。

## 更新与失效

原文件监听器更新代码索引后，语义视图由当前索引重新解析映射并比较局部指纹。未变化的方法与说明维持原确认；绑定方法的内容、参数、控制逻辑、关系或锚点变化会标记待复核。首批采用 AST 声明范围的内容哈希，包含完整方法体，粒度保守但不受相邻方法或行号变化影响。

当整文件哈希变化时，旧引文只允许在当前绑定声明内完整、唯一地重新定位；新的证据引用当前文件哈希，原始架构锚点不被修改。不能唯一匹配时保留人工解释并提示待复核。若唯一实现的内容确已变化，需先读当前源码，再显式采用新声明基准并重新审查；原锚点已失效或绑定歧义时，应修正原架构模型，不能只按同名方法自动确认。

「重新核验」重新计算本地映射和证据，不重写人工文字。所有读取/编辑请求核对 source/view/overlay 版本；过期视图会返回 409，源码面板会清除旧选择，避免代码与解释来自不同快照。

目前每次索引变化仍会重算已定义流程的轻量投影；局部指纹限制失效与审查范围，不等于底层索引已经具备全程序符号级增量分析。人工说明不会随扫描重生成。符号改名/移动后，显式选择器需同时在基础语义定义中维护；不会按同名或相似名称自动迁移。尚未提供运行时追踪、完整 CFG 或自动跨 HTTP JSON 值传播证明。

## 可重复验证

```powershell
# 在 Architecture-Explorer 工具目录执行；默认使用 config/local.json
powershell -ExecutionPolicy Bypass -File Tools/explorer.ps1 -Task Test
powershell -ExecutionPolicy Bypass -File Tools/explorer.ps1 -Task Typecheck
powershell -ExecutionPolicy Bypass -File Tools/explorer.ps1 -Task Build
pnpm verify-semantics
powershell -ExecutionPolicy Bypass -File Tools/explorer.ps1 -Task Dev
```

使用便携 Node 时，`pnpm verify-semantics` 的等价命令是 `.tools/node-v24.22.0-win-x64/node.exe node_modules/tsx/dist/cli.mjs Tools/verify-semantics.ts`。此命令读取已有授权索引及源码，核对映射和路径，输出步骤/关系/待复核数量；没有缓存时先执行既有 Scan 命令。所有测试变更均发生在工具 `.tmp` 夹具中，不修改 GameDemo02。
